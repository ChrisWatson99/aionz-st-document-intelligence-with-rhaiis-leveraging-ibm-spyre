3. Backend

FastAPI service in backend/: endpoints, data flow, RAG, storage and image pipeline.

Architecture

HTTP endpoints (server.py)

EndpointPurpose
POST /upload-filesAccepts PDF, DOCX, TXT and image files. Streams server-sent events: document_start, raw_content, summary_chunk and a completion event. After summarizing, it starts background ingestion with asyncio.create_task.
POST /user_exists_checkReturns the stored documents of a user. The frontend first tries GET and falls back to POST on a 405.
DELETE /delete-fileRemoves a document from MongoDB and OpenSearch.
POST /ask-queryRAG chat with streamed plain-text output. Supports document filtering by name, image retrieval and image-only mode.
GET /rhaiis/healthFeeds the status indicator in the UI header. See issues: it does not actually probe RHAIIS.

Summarization flow

  1. The file is written to /tmp using the base name and its text is extracted.
  2. The server sends the raw text to the client, then builds a summary prompt with build_summarize_prompt (up to about 16,000 characters of content).
  3. call_rhaiis_model_streaming posts to {RHAIIS_API_BASE_URL}/v1/chat/completions and relays tokens as SSE chunks.
  4. Document, summary, upload time, ROUGE score and image flag are stored in MongoDB (document_store, collection user_<id>). Duplicates are skipped.
  5. For non-image documents, ingest_code_to_os chunks and embeds the text into OpenSearch. Images are ingested in the background.

RAG chat flow

  1. The user query and the selected document names arrive as form data.
  2. retrieve_with_smart_fallback searches the user's index with k=5, filtered on metadata.doc_name.keyword. If the named documents are missing it falls back to all documents. Duplicate chunks are removed.
  3. If images are involved, ImageRAG.search_images adds image captions and metadata as context.
  4. build_rag_prompt detects the question language and builds a system instruction plus context in that language.
  5. The answer is streamed back as plain text.

Module details

rhaiis_utils.py

  • Model name sent in requests: ibm-granite/granite-3.3-8b-instruct.
  • MAX_TOKENS = 10000, MAX_PROMPT_LENGTH = 10000 (characters, prompt truncated), temperature 0.
  • TLS verification is turned off (ssl=False for aiohttp, verify=False for requests).
  • SimpleMetricsTracker records time to first token and tokens per second, estimating one token per four characters.
  • Older non-streaming helpers and a TLSAdapter remain in the file.

rag.py

  • Prompts exist in English, French, Portuguese, Hindi, German, Italian and Greek.
  • language_detection_tool (langdetect) drives the RAG prompt language.

utils.py

  • PDF text via PyPDF2, DOCX via python-docx.
  • chunk_code splits by lines: CHUNK_SIZE=25 lines with CHUNK_OVERLAP=4.

mongo_utils.py and opensearch_utils.py

  • Per-user MongoDB collection and per-user OpenSearch indexes (user_<id> for text, user_<id>_images for images).
  • Embeddings use HuggingFaceEmbeddings inside the app container (CPU or CUDA via torch).
  • ImageRAG uses openai/clip-vit-base-patch32 for embeddings and tries Granite Vision for captions, falling back to Salesforce/blip-image-captioning-base. The image index stores a knn_vector field sized from the CLIP projection dimension, plus the caption text.
Key observation. The only code path that reaches Spyre is the HTTP call to the RHAIIS endpoint. Every other AI component (embeddings, CLIP, captioning, language detection) is loaded locally by the backend.
